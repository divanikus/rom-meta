# RomMeta 0.1.0

The first public, pre-stable release of RomMeta prepares a portable local ROM
metadata catalog and uses it for local or network frontend output. Source code is MIT;
ROMs, BIOS, provider databases, artwork and video are not included.

## Included

- LaunchBox accepts unique compatible primary-name spelling variants, including
  word-boundary differences. Bounded hash lookup and conventional defaults prefer
  official releases over pirate/aftermarket variants.

- EmuMovies keeps edition/hardware qualifiers and selects a compatible regional
  release. Partial video acquisition retains previous source matches and records
  only successful downloads.

- DAT planning/import for No-Intro and Redump XML/ZIP inputs, classified MAME
  import, and ScummVM card acquisition. Existing source evidence is retained.
- Metadata/media acquisition from configured LaunchBox, OpenVGDB, IGDB,
  ScreenScraper, Hasheous and EmuMovies sources, with per-platform coverage,
  progress, resumable saved work and quota/error reporting. EmuMovies video
  selection requires exact platform identity or explicit aliases before quality
  preference, preventing cross-generation directory matches.
- Catalog validation, coverage reports, interactive regional fold and advanced
  hash-bound identity review. Fold preserves document-local YAML aliases when
  source fragments are regrouped; invalid expansion fails before publication.
- One `serve` for the read-only browser, consumer API and self-hosted Swagger UI.
  Defaults to loopback port 8787; shared-token protection is optional.
- Explicit selected-platform or whole-catalog Stats with progress/cancellation.
  Media inventories use ZIP central directories and bounded read concurrency.
- Offline ES-DE packages for supported cartridge, optical and arcade inputs:
  gamelists, selected media, preview, coverage and provenance. Single-system and
  batch exports leave input ROMs/catalogs unchanged. `--api` uses a remote catalog
  through the same `serve`, including `--all`, playlists and MAME. ROM bytes stay
  on the client; selected media downloads are SHA-256 checked before publication.
  Provider description entities decode for display while source YAML and explicit
  local overrides retain their original values.
- Configurable ES-DE display names: regional edition titles, full authority names
  or input filenames. Opaque square-bracket labels can be kept or dropped;
  automatic disambiguation considers the selected versions of each game within
  one system. Local and network exports use the same profile settings. See
  [display-name policy](../offline-export.md#display-names).
- A separate experimental RomM server importer in
  [examples/romm-importer](../../examples/romm-importer/README.md), with its own
  pinned runtime, setup, plan/apply/check workflow and tests. It fills existing
  scanned games through native handlers/models and Resources, not stock HTTP API.

## Install and first run

Windows and Linux **amd64** archives include the executable, user documentation,
examples and third-party license notices. Verify the download with `SHA256SUMS`,
extract it and, on Linux, run `chmod +x ./rom-meta`. Run `rom-meta --version` and
follow [README](../../README.md) or the [operator workflow](../cli-workflow.md).
Building from source requires the Go version in `go.mod` (1.26.3 or newer).

## Export coverage

ES-DE is the only implemented `export --target`. Nine cartridge families support
raw files and single-payload ZIPs. Selected optical systems support standalone
CHD/ISO; PSX/Saturn/Dreamcast also support directory playlists. PS3 and Xbox inputs
have format-specific limits. MAME uses a saved snapshot and exact set-name binding.
See the [format/scenario matrix](../export-scenarios.md) before planning a library.

### MAME limits

The user supplies ready ROM sets. Export maps ZIP or 7z archive set names through
a saved MAME snapshot. It does not inspect ROM components, prove version or
completeness, resolve parent/BIOS/sample/CHD dependencies, copy ROMs or rebuild sets.
Set compatibility with an emulator remains the user's responsibility. See the
[input format matrix](../export-scenarios.md#es-de-input-coverage).

The RomM example supports exact cartridge proofs and limited unverified CHD game
observations. It requires the matching RomM 5.4.0 runtime and administrator access
to native DB/Redis, library/config and Resources. It is not a general RomM plugin
or a version-independent client.

## Known limits

- Formats/commands may change before 1.0. Keep catalog and native-consumer backups.
- ES-DE/RomM integration is experimental. Supported input formats do not guarantee
  emulator compatibility or gameplay.
- Name/game-only binding, CHD header observations and arcade set names are weaker
  than exact payload proof. Unsupported or ambiguous inputs retain explicit reasons.
- No generic CUE/GDI/loose-M3U export, disc extraction/conversion, raw-disc proof,
  FBNeo exporter, ROM organizer or additional frontend template engine.
- Broad HDD/network Stats and first API index/stat passes can still be expensive.
  Provider accounts/quotas and downloaded content remain external requirements.
- Source licenses still govern metadata/media; generated output is not a bundled
  redistributable catalog.

Run the documented preview/plan before applying catalog or consumer changes.
