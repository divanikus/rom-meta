# RomMeta 0.1.0

RomMeta prepares a portable ROM metadata catalog and generates local/network
frontend output. Code is MIT; ROMs, BIOS, provider databases and media are not included.

## Included

- Linux arm64 binary alongside Windows/Linux amd64 builds.
- Inline and block fetch-source lists; malformed inline lists report configuration errors.
- No-Intro/Redump XML/ZIP DAT import, classified MAME import and ScummVM game lists.
- Metadata/media fetch from LaunchBox, OpenVGDB, IGDB, ScreenScraper, Hasheous and
  EmuMovies, with coverage, progress, resume and quota/error reporting.
  LaunchBox accepts unique compatible primary-name spelling variants; hash lookup
  and defaults prefer official releases. EmuMovies requires exact platform/alias,
  compatible edition/region and records only successful downloads. Normal stream
  closure no longer fails deadline renewal.
- Validation, coverage, interactive regional fold and hash-bound identity review.
  Fold preserves document-local YAML aliases and rejects invalid expansion before
  publication.
- One `serve` for read-only browsing, consumer API, Swagger and OpenAPI. Default:
  loopback port 8787, optional shared token. Stats supports explicit platform/full
  scans with progress/cancellation and bounded ZIP inventory reads.
- ES-DE packages with gamelists, selected media, preview and provenance. Local and
  `--api` export share `--all`, playlists and MAME; ROMs stay on the client and
  downloads are SHA-256 checked. Description entities decode for display without
  changing source YAML or explicit local overrides.
- [Display-name profiles](../offline-export.md#display-names): regional edition,
  full release or filename; opaque bracket labels; selected-version disambiguation.
- Experimental [RomM importer](../../examples/romm-importer/README.md) with its own
  plan/apply/check workflow, native handlers/Resources and pinned RomM 5.4.0 runtime.

## Install and first run

Windows **amd64** and Linux **amd64/arm64** archives include docs, examples and
dependency notices.
Verify `SHA256SUMS`, extract and, on Linux, run `chmod +x ./rom-meta`.
Check `rom-meta --version`, then follow [README](../../README.md) or the
[operator workflow](../cli-workflow.md). Source builds use the Go version in `go.mod`.

## Export coverage

ES-DE is the only built-in target: nine cartridge families (raw/single-payload
ZIP), selected optical systems (CHD/ISO), PSX/Saturn/Dreamcast directory playlists,
limited PS3/Xbox inputs and MAME set-name binding. See the
[format/scenario matrix](../export-scenarios.md).

### MAME limits

Users supply ready ZIP/7z sets. Export maps short names through saved snapshots;
it does not inspect components, prove version/completeness, resolve parent/BIOS/
sample/CHD dependencies, copy or rebuild ROMs. Emulator compatibility is separate.

The RomM example supports exact cartridges and unverified CHD game observations.
It needs matching RomM 5.4.0 runtime and administrator DB/Redis, library/config and
Resources access; a website login or stock API token is insufficient.

## Known limits

- Formats/commands may change before 1.0; retain catalog/native-consumer backups.
- Frontend integration is experimental; format support does not prove gameplay.
- Name/game-only matches, CHD observations and arcade names are weaker than payload
  proof. Unsupported/ambiguous inputs carry explicit reasons.
- No general CUE/GDI/loose-M3U export, disc extraction/conversion, raw-disc proof,
  FBNeo exporter, ROM organizer or additional frontend template engine.
- Broad HDD/network scans and initial API index/stat passes can be expensive.
  Provider access/quotas and content terms remain external requirements.

Preview catalog and consumer changes before applying them.
