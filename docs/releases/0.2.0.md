# RomMeta 0.2.0

This release adds prepared translations and ROM hacks, a standalone preparation
helper, broader catalog API/RomM imports, and source-matching fixes.

## Highlights

- **Translations and hacks:** retain their own fingerprints, language and credits
  while inheriting metadata/media from the original game. Exact base editions
  are optional; prepared CHD disc groups are supported.
- **Standalone `prepare-variants`:** discover compatible DAT/ZIP and published
  Gaming Alexandria, Romhack Archive and HackHash snapshots, review original-game
  links in the terminal, then create a separate staging catalog. Source-only
  workflows can use published output fingerprints without local ROMs. The helper
  runs without Go and does not modify its source catalog.
- **Broader RomM import:** catalog name/stat observations cover additional files
  and installed folders; MAME set names and PSP CHD metadata matching are improved.
  Translation cards prefer the original game's regional title, preserving custom
  names and locks.
- **Explicit release aliases:** record reviewed complete local names while
  preserving DAT release keys, authority and fingerprints. Ambiguous aliases
  remain unresolved in local and API lookup.

## Source and API fixes

- Catalog API lookups release parsed cards between requests and use a bounded
  Go memory budget in the server image.
- LaunchBox matching includes declared catalog aliases. ScreenScraper rejects
  responses for unrelated systems and stops resumably on daily quota responses.
- EmuMovies handles PSP Minis/WiiWare collection labels within the correct
  platform scope, retaining region, edition and ambiguity checks.
- Wii Digital CDN, Wii U Digital CDN and PS3 PSN Content keep distinct mappings
  from their disc catalogs, including the correct IGDB hardware names.
- Hasheous defaults to one request per second, honors header/JSON retry delays,
  and slows its shared request pace after HTTP 429. Existing explicit local rate
  settings remain in force; interrupted runs retain successful results.
- RomM cover handling, decimal fingerprint sizes, valid IGDB slugs and TOSEC
  authority preservation receive compatibility fixes.

## Install and upgrade

Choose Windows **amd64** or Linux **amd64/arm64** assets:

- `rommeta-0.2.0-<os>-<arch>.zip` — main CLI and documentation.
- `prepare-variants-0.2.0-<os>-<arch>.zip` — standalone helper and documentation.

Verify the common `SHA256SUMS`, extract, and on Linux run `chmod +x` on the
executable. Check `rom-meta --version` or `prepare-variants --help`.
See [the helper guide](../prepare-variants.md) and [source setup](../source-setup.md).

The experimental [RomM server importer](../../examples/romm-importer/README.md)
now targets **RomM 5.4.1** and checks the running server version. Rebuild its
matching environment when upgrading from the 5.4.0 example. Use a compatible
catalog server/client pair for new variant and release-alias workflows.

## Limits

Name/stat, CHD-header and MAME set-name matches are metadata associations, not
verified dumps or emulator compatibility checks. Provider coverage, credentials,
quotas and content terms still apply. ES-DE remains the only built-in export
target; RomM integration is a separate version-specific example. Catalog formats
and commands may change before 1.0. ROMs, BIOS, provider databases and downloaded
media are not included.
