# RomMeta 0.3.0-rc1

This release candidate adds LaunchBox export/enrichment, one shared frontend
workflow, and a library browser with export-profile preparation. Use it to validate
real collections and destination installations before the final 0.3.0 release.

## Highlights

- **LaunchBox:** create or enrich native cards from local/API catalogs, group
  regional releases and prepared variants as Additional Versions, select a primary
  input, and retain edition-specific multidisc playlists.
- **One export workflow:** ES-DE and LaunchBox share `export --target ...
  --destination ...`, preview by default and explicit `--apply`. Portable packages
  remain optional. Existing native fields, IDs, media and owner state are preserved;
  repeated unchanged application writes nothing.
- **Broader catalog coverage:** generic ROM-set handling follows catalog headers,
  while specialized cartridge/disc/playlist readers retain their evidence rules.
  Platform selection accepts codes, aliases and registered collection folder names.
- **Library and export preview:** inspect saved fields, alternate names, original
  Sources and Media. Switch the whole library to Export preview, adjust language,
  source order, media roles and original/reconstructed artwork preferences, then
  save a neutral YAML profile for the CLI.
- **Explainable inspection:** readable translation labels, selected-media reasons,
  registered fingerprint search, and native Raw XML templates help review the
  chosen output. Releases & fingerprints and Raw have their own card tabs.
- **Source intake:** named frontend gamelist collections retain provenance, with
  stricter hash/media association and release ownership. Provider matching and
  related-catalog lookup receive further compatibility fixes.

## Install and upgrade

Choose Windows **amd64** or Linux **amd64/arm64** assets:

- `rommeta-0.3.0-rc1-<os>-<arch>.zip` — main CLI and user documentation.
- `prepare-variants-0.3.0-rc1-<os>-<arch>.zip` — standalone variant helper.

Verify `SHA256SUMS`, extract to a separate program directory, and check
`rom-meta --version` or `prepare-variants --help`. Prebuilt programs do not need Go.
On Linux, make the extracted program executable with `chmod +x`.

Use matching current CLI/catalog-server builds for new export capabilities and
media roles. Keep the separately configured RomM importer compatible with its
pinned runtime; it is not a built-in filesystem export target.

Profiles may omit `target`; the CLI `--target` selects the frontend. Existing
version-1 profiles with an optional target marker remain accepted. Browser Save
profile creates a new neutral profile. Catalog/API origin, ROM roots and native
destination are command inputs rather than paths embedded into that profile.

Start with the [shared frontend guide](../frontend-export.md),
[LaunchBox guide](../launchbox-export.md), or
[browser/profile guide](../catalog-api.md#browse-with-an-export-profile).

## Candidate acceptance path

1. Inspect a small representative set in the browser, choose frontend/language/
   source/media settings, and save the profile.
2. Run CLI export against actual ROM inputs and a destination without `--apply`.
   Review matched/skipped inputs, media, versions, source-set preparation needs
   and native conflicts.
3. Close the frontend, apply the reviewed plan, then open it to inspect metadata,
   images and versions. Check emulator assignment and actual launches separately.
4. Repeat the same command and verify that unchanged output produces no writes.

## Limits

- Browser projection and Raw XML are catalog previews. They do not establish ROM
  identity, simulate an existing native merge, or contain final destination paths.
- The web UI remains read-only. Catalog editing, visual fold review, existing-profile
  import and direct native web application are future workflows.
- Native enrichment fills empty metadata and adds missing versions/media. Existing
  nonempty metadata and working main launch preferences are retained. Automatic
  consolidation of conflicting old LaunchBox cards and custom LaunchBox native
  media-folder overrides remain unsupported.
- Generic source packages may still need extraction/conversion and emulator setup.
  IBM PC/ScummVM remain excluded from built-in export. Ordinary flat M3U, CUE/BIN,
  GDI and PBP are not specialized launch inputs.
- Name/stat, CHD-header and MAME set-name associations are not verified dumps or
  proof of emulator compatibility. Multidisc switching and save behavior require
  actual emulator checks.
- Source credentials, quotas, coverage and content terms still apply. ROMs, BIOS,
  provider databases and downloaded media are not distributed with this release.
- Native arm64 hardware performance remains unmeasured; cross-build/emulated
  checks do not replace device performance measurements.
