# RomMeta 0.4.0

Manage a library from the browser, from the first DAT to a reviewed frontend export.
The CLI remains a full alternative and uses the same catalog, profiles and rules.

## New web workflows

- Import XML DAT/ZIP files into an empty library with a plan before applying.
- Fetch metadata and media for several platforms, choose providers and workers,
  queue jobs, follow stage progress and retry failures.
- Review duplicate cards side by side, collect decisions, and apply them together.
  The review counter and progress bar show how much remains. Backups are optional.
- Edit source fields in place, keep several named manual variants, validate Raw
  edits, and manage releases with their linked fingerprints in one form.
- Prepare ES-DE or LaunchBox export on the serve host. Save named profiles and
  destinations, configure media/source priorities, preview in a separate tab,
  and inspect actual native changes before applying.
- Review uncertain ROMs with live search and name suggestions. Accept all unique
  suggestions together, exclude inputs with checkboxes, then update the plan.
- Return to Operations after closing the browser. Use a compact platform action
  strip, status colors and dark/light themes.

See the [illustrated walkthrough](../web-walkthrough.md) and
[full library management guide](../catalog-editing.md).

## Fixes included in this release

An export with no recognized game cards now reaches review for both native targets.
Manual bindings can rebuild the retained plan; excluding all inputs finishes with
no output files. Related ports and editions no longer become ordinary merge
candidates without independent game-identity evidence. Their source relationships
remain intact, and explicit edition-family review remains available in the CLI.

## Upgrade and limits

Replace the executable, then restart `serve` when its jobs have finished. No catalog
migration is required. Existing named profiles, destinations and source settings
remain in the library. Enable writes explicitly with `serve --edit`.

- Operations survive browser closure while the server runs; they do not survive a
  server restart. Review choices must be submitted with **Update export plan**.
- Native exports use paths and permissions on the serve host. ROMs are not uploaded.
- Name suggestions need confirmation and do not verify a translation or release.
- Metadata providers can require accounts, impose quotas or lack platform coverage.
- RomMeta is pre-stable; command names and formats may change before 1.0.

Release bundles contain the main CLI or the standalone `prepare-variants` helper
for Windows amd64 and Linux amd64/arm64. Verify downloads with `SHA256SUMS`.
RomMeta distributes no ROMs, BIOS, provider databases or downloaded artwork.
